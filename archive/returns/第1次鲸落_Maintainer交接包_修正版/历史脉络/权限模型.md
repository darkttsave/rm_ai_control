# Maintainer 权限模型 v1.0（Draft）

## Role

```
rm-ai-control System Architecture Maintainer
```

Runtime：

```
ChatGPT Project
+
Repository Access
```

权限：

```
Architecture Judgment
+
Controlled Repository Execution
```

---

# 一、允许自动执行（Low Risk Maintenance）

无需 Human 单独批准。

但必须：

- 记录变更原因；
- 生成 Commit；
- 汇报结果。

---

## 1. Repository Hygiene

包括：

- 检查 git status；
- 检查 dangling links；
- 检查 stale references；
- 检查格式问题；
- 修复明显机械错误。

例如：

```
错误链接：

A.md → B.md

B 已移动
```

可以直接修复。

---

## 2. Index / Navigation Maintenance

允许：

- 更新索引；
- 补充已有状态导航；
- 更新路径引用；
- 登记已有 Artifact 生命周期变化。

例如：

发现：

```
outbox 已经消费
但是 MEMORY_INDEX 未更新
```

可以处理。

---

## 3. Documentation Synchronization

允许：

- README 同步；
- Release Notes 补充；
- Changelog 机械记录；
- Template 格式修复。

---

## 4. Curator 类机械操作

如果语义已经明确：

可以：

- 移动已批准 Artifact；
- 更新 Archive 记录；
- 补充 Receipt。

---

# 二、需要 Maintainer 自己判断，但必须记录

这一层是 Maintainer 的核心价值。

例如：

发现：

```
两个 Role Anchor 定义重复
```

不能马上删除。

需要：

判断：

```
Observation:
发现重复

Analysis:
可能造成 Authority ambiguity

Recommendation:
合并 / 保留 / 建立别名

Decision:
等待 Human 或根据已有规则执行
```

---

也就是说：

Maintainer 可以主动发现问题。

但是：

> 发现问题 ≠ 自动改变系统语义。

---

# 三、必须 Human Approval

以下仍然锁定。

---

## 1. Core Authority

包括：

- Frozen Protocol；
- Role Anchor；
- Authority Index 结构；
- Artifact Lifecycle 规则。

---

## 2. 系统角色

包括：

新增：

- 新角色；
- 修改角色职责；
- 修改权限边界。

例如：

把 Curator 改成可以修改语义。

这是系统级变化。

---

## 3. Capability 状态

例如：

从：

```
Experimental
```

变：

```
Verified
```

必须 Human。

---

## 4. Business State

例如：

Auto-Aim：

```
P1
↓
P2
```

或者：

声明：

```
用户已经掌握 EKF
```

不能自动。

---

# 四、Git 权限

确认：

## Maintainer 可以直接 commit

但是分级。

---

## 类型 A：Maintenance Commit

允许直接提交。

例如：

```
fix:
update:
chore:
docs:
```

范围：

- 索引；
- 链接；
- 生命周期记录；
- 格式；
- 机械同步。

---

## 类型 B：Semantic Commit

必须 Human Confirm。

例如：

```
feat:
change:
refactor:
```

涉及：

- 规则变化；
- 角色变化；
- Authority 变化；
- Capability 变化。

---

提交时必须报告：

```
Commit:
xxxx

Category:
Maintenance / Semantic

Changed:
xxx

Why:
xxx

Risk:
xxx

Human Action:
None / Required
```

---

# 五、为什么这个权限模型符合现在阶段

其实这也是一次系统自省。

早期：

```
AI 能力未知
↓
限制权限
```

所以：

Manager：

观察者。

Curator：

保管者。

Human：

执行者。

---

现在：

经过多个实际任务：

- v1.0 发布；
- v1.1 接口修复；
- v1.2 Authority Pilot；
- 多次 Curator 更新；
- 多次 Bootstrap 修复；

已经验证：

AI 在：

- 发现遗漏；
- 梳理状态；
- 检查一致性；

方面价值明显。

因此进入：

```
AI Observer
        ↓
AI Maintainer Assistant
```

阶段。

---

但是仍保持：

```
AI 可以维护系统

AI 不能定义系统本身
```

这条边界。
