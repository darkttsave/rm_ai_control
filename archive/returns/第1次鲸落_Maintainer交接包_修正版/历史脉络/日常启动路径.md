# 一、日常启动路径（Normal Recovery）

未来 Maintainer 每次启动：

## Step 1：Identity Recovery

读取：

```
Role Anchor
```

确认：

- 我是谁；
- 当前版本；
- 权限范围；
- Recovery Rule。

---

## Step 2：Authority Discovery

读取：

```
Authority Index
```

作用：

不是提供所有知识。

而是回答：

> 如果我需要某个规则，应该去哪里找？

例如：

需要：

```
Artifact Promotion
```

不用搜索整个仓库。

而是：

```
Authority Index
        ↓
UNIVERSAL_PROJECT_AI_BEHAVIOR
        ↓
对应 Section
```

---

## Step 3：Current State Recovery

读取：

```
Project Control Index

Memory Index

Latest Release Notes

Current Checkpoint
```

恢复：

```
现在系统是什么状态
```

---

## Step 4：Ready

只有当：

```
Identity PASS

Authority PASS

State PASS
```

才进入：

```
Maintainer Ready
```

---

# 二、深度恢复路径（Deep Recovery）

只有以下情况触发：

## 1. 大版本变化

例如：

```
v1.2 → v1.3
```

需要理解：

为什么变化。

---

## 2. 系统出现方向性冲突

例如：

发现：

```
Project Layer
与
Frozen Protocol
理念冲突
```

此时需要回溯：

```
Frozen Protocol
```

---

## 3. 新增核心机制

例如：

设计：

- 新角色；
- 新 Capability；
- 新生命周期规则。

需要恢复：

```
Protocol 原始设计
+
历史演化
```

---

# 三、临时大执行体机制

你提到的这个非常重要。

实际上解决了一个长期问题：

> Maintainer 不应该承担所有探索成本。

未来应该形成：

```
                    Human
                      |
                      |
                Maintainer
                      |
        ----------------------------
        |                          |
  日常维护                    临时 Research Executor
        |                          |
  小范围修改                大规模探查/分析
```

---

## Maintainer 的职责

不是：

“亲自读完整个世界”。

而是：

判断：

> 什么时候值得调用更大的分析资源。

例如：

发现：

```
我要修改 Knowledge System

但不知道历史设计
```

Maintainer 不应该自己消耗大量上下文。

可以创建：

```
Protocol Archaeology Task
```

交给临时执行体。

---

# 四、大执行体的定位

它不是新的长期角色。

这是一个：

## Disposable Research Executor

特点：

- 高额度；
- 长上下文；
- 单次任务；
- 不持有长期 Authority。

任务结束：

返回：

```
Research Report
```

然后：

Maintainer 判断是否采用。

---

例如：

## 任务：

“分析 Frozen Protocol 到 v1.2 的演化”

执行体：

读取：

```
protocol/
control/
release/
```

输出：

```
Evolution Report
```

Maintainer：

决定：

是否更新系统。

---

# 五、这其实保护了 Maintainer 的上下文

这是非常重要的。

长期角色最大风险：

不是能力不足。

而是：

> 长期上下文被大量一次性任务污染。

例如：

今天：

- 分析 Protocol；
- 明天：
- 审查 Auto-Aim；
- 后天：
- 调研 DSH。

如果全部塞给 Maintainer：

最后：

它记住很多细节，但是忘记自己的核心职责。

所以应该：

```
Maintainer
=
系统长期状态守护者

Research Executor
=
临时高强度分析工具
```
