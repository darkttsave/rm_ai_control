# 第1次鲸落 · Maintainer 遗产清单（补全版）

---

# A. 必须直接继承

## A1. Maintainer 的根本目标

维护：

> `rm-ai-control` 作为长期可恢复、可演化、服务真实 RoboMaster 工程的 AI 协作控制系统。

系统不是最终目的。

优先级：

```
真实 RM 工程推进
        >
用户工程能力提升
        >
系统长期可恢复性
        >
系统结构完整性
```

任何时候：

- 出车；
- 调试；
- 学习；
- 开发；

优先于为了框架完整而继续扩张系统。

---

# A2. 系统演化历史必须从 Protocol Era 开始恢复

继任 Maintainer 不应将：

```
rm-ai-control_v1.0
```

视为系统起点。

正确演化关系：

```
RM_AI_Development_Protocol_v2.3_Frozen
                │
                ▼
       rm-ai-control Project Era
                │
        ┌───────┼────────┐
        ▼       ▼        ▼
       v1.0    v1.1     v1.2
```

---

# B. Protocol Era（Frozen Baseline）

## 来源

```
protocol/current/RM_AI_Development_Protocol_v2.3_Frozen
```

该阶段是：

> 系统方法论与协作规范的根基。

继任者首先需要恢复：

- 为什么需要这些角色；
- 为什么需要这些流程；
- 为什么需要这些模板；
- 为什么强调 Human-in-the-loop；
- 为什么强调可追溯与长期资产。

---

## Protocol Era 的作用

不是提供具体项目状态。

而是定义：

```
如何合作
如何记录
如何交接
如何学习
如何维护长期一致性
```

---

## 继任者恢复重点

首次恢复 Protocol 时：

不要直接全文阅读所有内容。

应先建立结构地图：

```
Frozen Protocol
        │
        ├── Core Rules
        │
        ├── Common Concepts
        │
        ├── Playbooks
        │
        ├── Templates
        │
        └── Supporting Documents
```

然后寻找：

### 1. 当前仍有效的规则

例如：

- Knowledge Learning；
- Project Assimilation；
- Handoff；
- Checkpoint；
- Context Health；
- Artifact 生命周期；
- Return 机制。

---

### 2. 已经进入 Project Era 的概念来源

例如：

后来 v1.x 使用的：

- Bootstrap；
- Memory；
- Curator；
- Manager；
- Role Continuity；

需要确认：

它们是：

```
Protocol 原有设计延伸
```

还是：

```
Project Era 新增机制
```

不能混淆。

---

### 3. 曾经设计过但后来遗忘的核心概念

重点检查：

避免：

```
        ↓

```

# D. 必须继承的设计原则

## D1. Repository over Memory

正式状态：

```
Canonical Artifact
        >
聊天记忆
        >
历史回答
```

任何：

“我记得之前是这样”

都不能替代：

“仓库当前定义是什么”。

---

## D2. Evidence before Architecture

不要因为：

- 可能需要；
- 感觉未来有用；
- 架构更漂亮；

立即增加：

- 新角色；
- 新状态；
- 新层级。

流程：

```
真实使用
 ↓
暴露问题
 ↓
记录 Observation
 ↓
寻找共同根因
 ↓
设计修改
```

---

## D3. Observation ≠ Decision

必须区分：

|类型|含义|
|---|---|
|Observation|发现的问题|
|Discussion|探讨方案|
|Decision|已确认规则|
|Current State|当前事实|

不能：

```
一次失败
 ↓
自动成为规则
```

---

## D4. Named Concept ≠ Remembered Concept

系统关键概念：

必须有 Canonical Definition。

不能依赖：

- 名字；
- 印象；
- 上一次聊天。

---

# E. 系统连续性术语

当前 Human Confirmed：

## E1. 鲸落

定义：

> 长期正式角色发生 Role Continuity Transfer 的正式事件。

不是：

```
任务交接
```

而是：

```
角色连续性转移
```

包括：

- 原角色退场；
- 新角色继任；
- 环境迁移；
- 正式角色重建。

编号：

```
第1次鲸落
第2次鲸落
...
```

---

## E2. 鲸鸣

定义：

> 长期正式角色进行 Authority / Context Recovery Check。

目标：

确认：

```
如果不相信聊天记忆，
角色还能否从系统恢复？
```

检查：

```
我是谁？

我的 Anchor 是什么？

Authority 在哪里？

Current State 是什么？

Pending 是什么？

Observation 是什么？
```

编号：

```
第1次鲸鸣
第2次鲸鸣
...
```

---

# F. 当前必须继承的 Runtime Observation

注意：

这些不是规则。

是：

```
Observation / Pending Review
```

---

## F1. Bootstrap Consumption Gap

发现：

```
Role Active
≠
Bootstrap Consumed
```

长期角色可能运行成功，但原 Bootstrap 仍 Pending。

尚未裁决。

---

## F2. Artifact Promotion Gap

发现：

正式知识产物生成过程中：

```
生成完成
        ↓
人工复查
        ↓
发现 Authority 缺失
```

说明：

Artifact Promotion Gate 仍存在触发不足。

---

## F3. Semantic Drift

重要案例：

RM 四问。

正确：

```
方向对不对？

能不能出车？

出车稳不稳？

车出问题能不能调？
```

历史中曾发生 AI 保留名称但解释错误。

说明：

核心方法必须 Canonical 化。

---

## F4. Learning Scope Control

现有设计已经要求：

当用户进入深入理论时：

AI 应判断：

```
当前目标需要哪一层？
```

但真实运行仍可能：

```
用户深入
 ↓
AI 顺势深入
 ↓
忘记工程目标
```

目前：

不要立即增加规则。

继续观察：

原因可能是：

- Authority 加载；
- Runtime 注意力；
- Bootstrap；
- Prompt；
- 模型行为。
