# 2. Scenario Validation

## A. 工程突然出现知识断点

预期：

```text
Learning_Knowledge_Debt
→ 判断 Required Engineering Control
→ Knowledge Layer
→ Engineering Use / Working Understanding
→ Sufficiency Check
→ 回工程
```

结果：**PASS**

没有要求自动进入 Deep Study。

---

## B. 后续决定真正系统学习同一主题

预期：读取已有 Learning State，利用已有理解，不从头重复；AI 根据追问自然加深。

结果：**PASS**

由 `Intent-driven Adaptive Explanation` + `Overview + Relevant Detail` 支持。

---

## C. 同一对话从 API 切到理论

预期：用户不操作 Mode；AI 做 Meaningful Shift 提示，然后继续。

结果：**PASS**

提醒限制为短说明，不生成状态报告。

---

## D. 单点问题会膨胀成完整知识板块

预期：AI 说明当前任务需要哪一层、继续深入会进入什么，再由用户决定。

结果：**PASS**

由 Scope Expansion 规则覆盖。

---

## E. 学习对话太长，需要换聊天

普通 Knowledge Conversation：

```text
LEARNING_THREAD_STATE_TEMPLATE
→ LEARNING_THREAD_STATE
→ 新对话恢复
```

正式 Project Specialist：

```text
SPECIALIST_CHECKPOINT
+ Knowledge Payload
```

不额外维护第二份 Thread State。

结果：**PASS**

避免与 v2.2 Specialist / common 重复造状态。

---

## F. 新知识需要联系已有 PnP / EKF / TF2 等经验

预期：Learning State 允许 AI 建桥，但“接触过 / 有资产”不等于可靠前置。

结果：**PASS**

Learning State 与 Asset Index 已分离。

---

## G. 同方向存在两份笔记

预期：先判断知识职责，而不是按标题 / 主题机械合并。

结果：**PASS**

支持：

- New；
- Update；
- Merge / Supersede；
- 同主题不同职责共存。

---

## H. 旧知识重构

预期：原来源只读、Semantic Coverage、历史任务状态和本次 Rewrite Status 分开、重要代码注释有明确去向。

结果：**PASS**

由 `Legacy Reconstruction` Operation 覆盖。

---

## I. 十分钟普通答疑

预期：不生成 State Patch / Thread / Asset Patch / Formal Note。

结果：**PASS**

Knowledge Playbook 明确允许“直接回答即可”。

---

## J. 项目驱动知识专项

预期：继续使用 Supervisor → Specialist 拓扑，Knowledge Layer 只作为 Specialist 方法。

结果：**PASS**

没有创建第二套 Knowledge Specialist Role。

---

## K. 第一次启用 v2.3

预期：不要求全量知识库建档。

结果：**PASS**

`KNOWLEDGE_PROMPT_CARDS.md` Card 0 仅创建最小 Learning State + Asset Index，并采用 Usage-driven Incremental Registration。

---

## L. 初始化输入随时间增长

预期：不全量塞入。

结果：**PASS**

统一使用：

```text
Global Overview
+
Relevant Detail
```

# 4. Remaining Validation Boundary

- 真实制导镖学习对话中的提醒频率是否合适；
