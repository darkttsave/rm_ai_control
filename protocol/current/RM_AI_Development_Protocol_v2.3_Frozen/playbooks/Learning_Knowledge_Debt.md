# Playbook --- Learning / Knowledge Debt

> v2.3 延续：**出了问题会不会修**，同时避免学习阻塞"造不造得出来"。

> 场景：工程任务依赖陌生或尚未充分理解的知识。\
> 目标：既不要求"全部学完才能开发"，也不允许代码长期脱离人的理解。

------------------------------------------------------------------------

# 1. Learning 与 Engineering 不互相冒充完成

``` text
代码跑通
≠
知识已经掌握

知识讲懂
≠
工程已经验证
```

工程需要的是当前责任下足够的控制力。

学习需要的是可迁移理解。

二者可以互相触发，但完成标准不同。

------------------------------------------------------------------------

# 2. Minimum Viable Learning

时间紧时允许：

``` text
Skeleton First
→ Depth On Demand
```

先回答：

1.  这个东西是什么？
2.  它在当前 RM 系统哪里？
3.  输入是什么？
4.  输出是什么？
5.  当前必须理解什么？
6.  误解它会造成什么风险？
7.  当前暂时不需要深入什么？
8.  出现什么情况必须回来补？

做到这些以后，可以继续当前工程。

------------------------------------------------------------------------

# 3. Engineering Control 决定学习深度

## 准备 Tune

至少知道：

-   参数语义；
-   调整方向；
-   观测量；
-   合理范围；
-   风险；
-   回滚。

## 准备 Diagnose

至少知道：

-   主数据流；
-   关键状态；
-   正常行为；
-   主要失败域；
-   第一批证据。

## 准备 Modify

至少知道：

-   当前设计为什么存在；
-   关键 Contract；
-   Invariant；
-   修改影响范围；
-   如何验证没有破坏旧行为。

## 准备 Robot Integration

至少知道：

> 如果这条关键链路现在坏了，我第一步查哪里？

------------------------------------------------------------------------

# 4. Knowledge Debt

Knowledge Debt 不是失败，而是：

> **已经知道自己暂时没深入什么，并知道风险和回看条件。**

推荐最小字段：

``` text
Topic:
Why deferred:
Current safe assumption:
Trigger to revisit:
```

例如：

``` text
Topic:
ONNXRuntime 线程调度细节

Why deferred:
当前固定配置已经经过性能验证

Trigger:
准备修改 thread 参数或出现性能瓶颈
```

------------------------------------------------------------------------

# 5. Knowledge Debt 不要求全部清零

优先偿还：

-   会影响现场调参；
-   会影响故障定位；
-   会影响外部接口；
-   会影响安全；
-   当前准备修改的关键模块。

不要为了"知识体系完整"阻塞紧迫工程。

------------------------------------------------------------------------

# 6. 防止认知 WIP 无限扩张

如果同时存在大量：

``` text
AI 改过
但我还没有建立主链路理解
```

就应该停止继续扩大新模块。

建议同时只有少量高变化、低理解区域。

稳定模块应逐渐达到：

-   主链路知道；
-   参数会调；
-   故障会定位。

------------------------------------------------------------------------

# 7. Learning → Engineering 的最小桥接

这次协议不强制 EKC / Bridge Candidate 系统。

只在真正存在：

> "这条知识在代码里不能弄错"

时，把它压缩成工程约束，放到最合适的位置：

-   接口文档；
-   代码附近；
-   Architecture Decision；
-   Agent Context；
-   项目文档。

至少说明：

``` text
Constraint
Scope
Reason
Validation / Source
```

完整学习笔记继续服务人的理解，不整篇塞给工程 Agent。

------------------------------------------------------------------------

# 8. 什么时候需要系统学习

出现以下情况之一，可以升级为更深入学习：

-   同一 Knowledge Debt 多次阻塞任务；
-   当前理解无法安全 Modify；
-   需要解释核心 trade-off；
-   需要从零重建该模块；
-   该知识已成为长期负责领域的核心能力。

深度由真实责任触发，而不是第一次见到名词就自动进入完整课程。


------------------------------------------------------------------------

# 9. 进入 Knowledge Layer 的边界

本 Playbook 负责回答：

> **现在值不值得学？当前责任要求学到什么工程控制等级？**

一旦已经决定真正学习，不要继续在这里扩展完整教学方法。

进入：

`knowledge/KNOWLEDGE_LEARNING_AND_NOTES.md`

完整关系：

``` text
Knowledge Debt
→ 确定当前 Required Engineering Control
→ Knowledge Layer
→ 达到 Knowledge Sufficiency
→ 回工程
```

Knowledge Layer 不以“完全掌握”为退出条件。

只要当前理解已经足以安全支持计划中的：

- Operate；
- Tune；
- Diagnose；
- Modify；

中的真实责任，就可以回到项目。

如果后续责任升级，再按 Trigger 回来继续补。
