# Playbook --- Integration / Robot Safety

> v2.3 继承：**造不造得出来 + 稳不稳定**；安全始终是硬约束。

> 场景：模块开始接真实上下游、真实硬件或真实机器人。\
> 原则：**Implemented ≠ Integrated；Simulation ≠ Robot.**

------------------------------------------------------------------------

# 1. 尽早打通真实边界

RM 项目不适合：

``` text
Detector 完全完成
→ Tracker 完全完成
→ Serial 完全完成
→ 最后一天第一次联调
```

更适合：

``` text
薄 Walking Skeleton
→ 第一次 Integration
→ 暴露最大风险
→ 局部强化
→ 再 Integration
```

真实边界越晚出现，前期假设越可能堆积。

------------------------------------------------------------------------

# 2. 外部依赖没有完成时

例如：

``` text
视觉已完成
STM32 未完成
```

只模拟当前模块真正依赖的边界：

``` text
ARRIVE_BEAN
ACK
ARRIVE_DIGIT
```

不要为了"完整"模拟对方整个系统。

状态应诚实标记：

``` text
Locally Verified
Integration Pending
```

------------------------------------------------------------------------

# 3. 未联调阶段不要过度 Harden

在真实问题尚未出现前，只实现：

-   明确 Contract；
-   最小 Stub；
-   必要超时/错误处理；
-   基础日志；
-   可撤销测试手段。

不要因为无法真实验证，就凭想象增加：

-   多层自动恢复；
-   多重 fallback；
-   动态策略切换；
-   复杂重连状态机；
-   多种备用协议。

真实故障出现后再 Harden。

------------------------------------------------------------------------

# 4. 模块成熟顺序

推荐理解为：

``` text
Skeleton
→ Baseline
→ Integrated
→ Hardened
```

`Hardened` 的依据应主要来自：

-   真实联调问题；
-   真机故障；
-   已知安全要求；
-   实际比赛环境。

不是第一天就预测所有异常。

------------------------------------------------------------------------

# 5. 真机前 Safety Gate

对本次变化涉及的链路检查：

## Units

-   rad / deg？
-   mm / m？
-   rpm / rad/s？
-   timestamp 单位？

## Direction / Frame

-   电机正方向；
-   yaw / pitch 定义；
-   相机/云台/odom/world frame；
-   坐标变换方向。

## Limits

-   输出限幅；
-   速度/电流/力矩限制；
-   积分饱和；
-   Dead zone；
-   数据异常范围。

## Timing

-   控制周期；
-   timeout；
-   watchdog；
-   通信延迟；
-   stale command。

## Failure Behavior

-   CAN / Serial 断开后怎样；
-   上位机进程退出后怎样；
-   最后一个指令是否会被保持；
-   是否有安全归零；
-   急停是否真正切断危险输出。

未知的安全事实触发 Human Gate。

------------------------------------------------------------------------

# 6. 第一次真机测试

优先：

-   低风险工况；
-   小幅输出；
-   明确急停；
-   一次验证一个主要链路；
-   有人观察硬件；
-   必要时记录现场数据。

不要把"编译通过→直接满功率下地"当测试。

------------------------------------------------------------------------

# 7. Integration 验证内容

至少记录：

``` text
真实上游：
真实下游：
使用配置：
成功标准：
观察结果：
当前 Verification Level：
剩余 Pending：
```

如果只是 Stub 测试，不得写成 Integration Verified。

------------------------------------------------------------------------

# 8. 联调后的收敛

真实 Integration 成功后及时检查：

-   Stub 是否删除；
-   Mock mode 是否退出生产代码；
-   临时协议兼容是否删除；
-   测试参数是否恢复；
-   调试输出是否需要保留为正式 Observability；
-   新发现的故障是否值得 Harden。

这样联调不会留下永久的"临时工程层"。
