# Carry Forward --- 通用阶段延续约定

> `Carry Forward` 是一个非常小的机制：
>
> **明确下一阶段必须带走什么。**
>
> 它不保存全部历史，也不替代 Report / State / Brief。

------------------------------------------------------------------------

# 1. 为什么需要它

很多交接失败不是因为"没有总结"，而是因为：

> 总结写完了，但没人知道下一阶段到底哪些信息是必须携带的。

因此阶段性产物末尾统一增加：

``` text
## Carry Forward

下一阶段必须携带：
- ...
- ...
- ...
```

------------------------------------------------------------------------

# 2. Carry Forward 应该包含什么

只包含：

-   会改变下一阶段判断的事实；
-   已冻结的重要决定；
-   当前仍有效的约束；
-   必须继续追踪的 Unknown；
-   下一阶段需要访问的关键材料；
-   下一阶段的第一步。

------------------------------------------------------------------------

# 3. 不应该包含什么

不要塞：

-   完整历史；
-   所有讨论过的方案；
-   没采纳的 brainstorm；
-   普通知识解释；
-   与下一阶段无关的原始材料。

------------------------------------------------------------------------

# 4. Carry Forward 与其他对象的关系

``` text
Checkpoint
→ 当前阶段还没结束，帮助同阶段继续

Report
→ 当前阶段结束，向下一阶段交付

Carry Forward
→ 明确 Report / Checkpoint 中哪些内容必须带走

Brief
→ 一个具体任务交给下游

State
→ 当前客观事实

Snapshot
→ 当前主线工作态
```

------------------------------------------------------------------------

# 5. 最小模板

``` text
## Carry Forward

必须带走：
- Current Goal：
- Verified Facts：
- Locked Decisions：
- Active Constraints：
- Open Questions：
- Required Materials：
- First Next Step：
```

不需要每项都有内容。

------------------------------------------------------------------------

# 6. 一个判断标准

问：

> **如果下一阶段完全看不到当前聊天，这一项丢失会不会改变它的判断？**

会：

> Carry Forward。

不会：

> 不要放进去。
