# Conversation Continuity --- 通用任务连续性

> 本文件是通用层，不依赖 RoboMaster。
>
> 目标：
>
> **长期任务即使跨越多个对话、角色或执行体，也不依赖完整聊天历史才能继续。**

------------------------------------------------------------------------

# 1. 基本原则

不要试图保存所有聊天。

真正需要保存的是：

> **下一次工作继续所需的最小当前状态。**

因此：

``` text
完整聊天历史
≠
可靠任务状态
```

------------------------------------------------------------------------

# 2. 信息应该分层

  信息                 推荐位置                         回答的问题
  -------------------- -------------------------------- --------------------------
  Current Truth        代码 / 数据 / 事实文档 / State   现在客观是什么？
  Current Work State   Snapshot                         当前主线在推进什么？
  Stage State          Checkpoint                       当前阶段做到哪里？
  Stage Result         Report                           这个阶段最终得出了什么？
  Handoff              Brief / Carry Forward            下一角色到底需要什么？
  History              Git / Archive / Logs             过去为什么这样？
  Knowledge            Knowledge Base                   长期应该记住什么？

不要让一个文件承担全部记忆。

------------------------------------------------------------------------

# 3. Entry

`Entry` 解决：

> **新角色 / 新阶段第一次进入时应该以什么身份、在什么边界内工作？**

Entry 是稳定规则。

不要把动态项目状态塞进 Entry。

------------------------------------------------------------------------

# 4. Checkpoint

`Checkpoint` 解决：

> **当前阶段还没有结束，但这个对话不适合继续了。**

它应该足以让新的同阶段对话继续。

推荐最小结构：

``` text
Current Stage
Current Goal
Verified Progress
Important Decisions
Open Questions
Current Materials
Next Step
Carry Forward
```

Checkpoint 不是阶段总结论文。

在具体应用协议中，如果已经提供 Checkpoint Template，应严格按模板生成，不让 AI 临场发明格式。RM 应用见 `templates/STAGE_CHECKPOINT_TEMPLATE.md`。

------------------------------------------------------------------------

# 5. Report

`Report` 解决：

> **当前阶段已经结束，需要把结果交给下一阶段。**

Report 可以比 Checkpoint
更完整，但仍然应该只保存下一阶段真正有用的结果。

在具体应用协议中，如果已经提供 Report Template，应按对应模板生成。RM 的 P0 / P1 / P2 Report Template 位于 `templates/`。

Report 最后必须有：

``` text
Carry Forward
```

------------------------------------------------------------------------

# 6. Carry Forward

`Carry Forward` 解决：

> **如果下一阶段完全看不到当前聊天，什么信息必须被带过去？**

它不是复制所有内容。

应该是一个短列表：

``` text
下一阶段必须携带：
- ...
- ...
- ...
```

------------------------------------------------------------------------

# 7. Brief

`Brief` 解决：

> **一个已经确定的具体任务如何交给下游角色？**

Brief 不等于 Report。

Report 描述阶段结果。

如果应用协议已经提供 Brief Template，应按对应模板生成，而不是自由发挥。

Brief 描述：

``` text
你现在要完成什么
+
完成它需要知道什么
+
什么不要碰
+
怎么验证
```

------------------------------------------------------------------------

# 8. 同阶段换对话

如果任务没有变化，只是当前上下文不再可靠：

``` text
旧对话
→ Checkpoint
→ 新对话
→ Entry
+
Checkpoint
+
Carry Forward
+
本轮新材料
```

不要复制完整历史。

------------------------------------------------------------------------

# 9. 跨阶段交接

``` text
阶段 A
→ Report
→ Carry Forward
→ 阶段 B
```

原则：

> **Report 是导航层，原始材料是证据层。**

如果阶段 B 对某个结论有疑问，再回查原始材料。

------------------------------------------------------------------------

# 10. Supervisor / Specialist / Executor 不是唯一适用对象

同样的方法适用于：

-   学习项目；
-   软件开发；
-   游戏开发；
-   研究；
-   写作；
-   长期调研；
-   任何跨多次对话的任务。

------------------------------------------------------------------------

# 11. Recoverability Test

任何准备换对话 / 角色的时刻，可以问：

> **如果当前聊天现在完全消失，新角色只拿到 Entry + 当前事实 + Checkpoint
> / Report / Brief，它还能继续下一步吗？**

能：

> Handoff Ready。

不能：

> 先把缺失的关键状态收敛出来。

------------------------------------------------------------------------

# 12. 最小主义

如果连续性文件开始越来越长，先检查：

-   是否混入历史；
-   是否复制已有事实文档；
-   是否把聊天流水账写进去了；
-   是否把"可能以后有用"误当成当前必须恢复。

连续性的目标不是保存过去。

> **目标是保证下一步可以继续。**
