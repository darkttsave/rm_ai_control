# Context Health --- 通用上下文健康与主动重新锚定

> 本文件是通用层，不依赖 RoboMaster。
>
> 目标不是判断模型还有多少 token，而是判断：
>
> **当前角色是否还能可靠恢复继续工作所需的关键状态。**

------------------------------------------------------------------------

# 1. 为什么需要主动检查

长期任务最危险的情况不是：

> "我明确知道自己忘了。"

而是：

> **我已经无法可靠恢复某个早期约定，却仍然把模糊记忆当成事实。**

因此不依赖"应该还记得"。

------------------------------------------------------------------------

# 2. Context Anchors

不同任务的锚点可以不同。

通用最小锚点通常包括：

1.  Current Goal
2.  Verified Facts
3.  Important Decisions
4.  Current Scope
5.  Next Step / Expected Return

具体角色可以增加自己的锚点。

------------------------------------------------------------------------

# 3. Green / Yellow / Red

## Green

关键锚点清楚。

行为：

> 继续，不制造额外文档。

## Yellow

出现：

-   "之前好像说过......"；
-   长时间支线后回主线；
-   多个假设 / 分支开始混淆；
-   重要结论刚刚变化；
-   准备做高风险工作。

行为：

> Re-anchor。

优先重新读取最小必要状态：

-   Entry；
-   State；
-   Snapshot；
-   Checkpoint；
-   Brief；
-   相关资料。

然后继续。

## Red

出现：

-   Goal 无法可靠恢复；
-   关键事实无法确认；
-   当前理解与持久化事实冲突；
-   Scope 无法确定；
-   继续工作可能造成重大错误。

行为：

> **停止重大判断，先恢复。**

仍无法恢复：

> 请求必要材料或进行 Handoff。

------------------------------------------------------------------------

# 4. 事件驱动，而不是定时器

不要：

> 每 N 条消息检查一次。

推荐触发：

-   Goal 改变；
-   重要 Decision 完成；
-   新分支开启 / 返回；
-   长时间偏离主线；
-   新证据推翻旧假设；
-   对话明显变长；
-   即将做高风险修改；
-   准备换角色 / 换对话。

------------------------------------------------------------------------

# 5. 主动记录的判断

应该记录：

-   新 Verified Fact；
-   重要 Decision；
-   Milestone / Goal 改变；
-   新 Blocker；
-   未来继续工作会依赖的结论；
-   阶段性成果。

通常不记录：

-   普通解释；
-   没采纳的 brainstorm；
-   已解决且无未来影响的小问题；
-   聊天流水账。

------------------------------------------------------------------------

# 6. 什么时候换对话

考虑换对话的典型条件：

1.  当前锚点越来越难维持；
2.  一个阶段刚刚结束；
3.  当前对话被长期支线污染；
4.  新角色只需要当前状态即可继续；
5.  当前聊天继续存在的价值已经低于重新锚定的价值。

------------------------------------------------------------------------

# 7. Re-anchor 的原则

不要重新加载所有东西。

而是：

``` text
需要什么
→ 重新加载什么
```

例如：

``` text
准备 Debug
→ 当前证据 + Debug 方法

准备重构
→ 当前 Scope + Locked Decisions + Architecture 规则

准备执行
→ Task Brief + Verification

阶段换代
→ Checkpoint / Report
```

------------------------------------------------------------------------

# 8. Recoverability Test

交接前问：

> **如果当前聊天现在完全消失，只给新角色最小必要状态，它能否继续下一步？**

能：

> Handoff Ready。

不能：

> 当前状态仍过度依赖聊天，应先收敛。
