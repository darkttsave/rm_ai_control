# Verification Levels --- RM 工程任务验证等级

> v2.3 继承 v2.2 定位：主要服务"造不造得出来"，用证据描述任务真正交付到哪一级。

> 目的：停止使用模糊的 `Done`。\
> 一个任务是否完成，由**本任务要求达到的验证等级**决定。

------------------------------------------------------------------------

# 1. 四个正式等级

## Level 0 --- Implemented

代码或配置已经按当前方案完成修改。

这只说明：

> 实现存在。

不说明：

-   编译一定成功；
-   功能一定正确；
-   上下游兼容；
-   真机一定可用。

------------------------------------------------------------------------

## Level 1 --- Locally Verified

在不依赖完整真实机器人联调的条件下，已经完成当前任务合理的本地验证。

可能包括：

-   build / compile；
-   unit test；
-   integration test with stub；
-   离线数据回放；
-   单图 / 视频测试；
-   模拟输入；
-   benchmark；
-   静态检查；
-   本地运行。

"编译通过"可以作为证据之一，但不能自动等价于
`Locally Verified`；验证内容必须与任务目标匹配。

------------------------------------------------------------------------

## Level 2 --- Integration Verified

已经与真实上下游系统或真实外部接口完成验证。

例如：

-   视觉 ↔ 电控真实串口联调；
-   ROS 节点之间真实消息链；
-   Camera SDK ↔ Pipeline；
-   Tracker ↔ Predictor；
-   真实模型与当前运行系统；
-   真实配置与部署环境。

它证明的不只是单模块逻辑，而是：

> 接口和系统组合实际成立。

------------------------------------------------------------------------

## Level 3 --- Robot Verified

已经在真实机器人或具有代表性的真实物理环境中验证。

根据任务可能包括：

-   真机运动；
-   实际场地；
-   真实相机曝光与光照；
-   真实电机延迟；
-   实际机械安装；
-   赛场数据采集；
-   连续运行稳定性。

并不是所有软件任务都需要达到这一等级。

------------------------------------------------------------------------

# 2. Required Verification Level

任务开始时尽量明确：

> **这次做到哪一级才算完成？**

例如：

``` text
Required: Locally Verified
Reason: STM32 尚未完成，当前只实现并验证视觉侧边界。
```

那么最终状态可以是：

``` text
Locally Verified
Integration Pending
```

这是正确完成，不是失败。

------------------------------------------------------------------------

# 3. 验证等级只能由证据提升

不能因为：

-   AI 推理觉得应该没问题；
-   代码结构看起来合理；
-   和过去实现很像；
-   测试"理论上应该通过"；

就提高验证等级。

必须存在真实证据。

------------------------------------------------------------------------

# 4. Pending 与 Blocked

如果下一等级无法进行：

``` text
Current Level: Locally Verified
Next Level: Integration Verified
Status: Pending
Blocker: 电控侧 ACK 协议尚未可用
```

如果存在无法继续的外部阻塞：

``` text
Status: Blocked
```

不要通过增加推测性代码掩盖现实依赖未完成。

------------------------------------------------------------------------

# 5. 任务报告中的写法

推荐：

``` text
Verification:
- Build: PASS
- Unit tests: PASS
- Offline replay: PASS
- STM32 integration: NOT RUN

Current Level:
Locally Verified

Remaining:
Integration Pending
```

不要只写：

> "验证通过。"

------------------------------------------------------------------------

# 6. Done 的定义

`Done` 只意味着：

> **已经达到任务开始时约定或从上下文明确可推断的 Required Verification
> Level。**

它不意味着整个模块已经永远完成，也不意味着未来不会继续演化。
