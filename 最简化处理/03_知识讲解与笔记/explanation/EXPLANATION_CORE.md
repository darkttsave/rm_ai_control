# Explanation Core — 技术讲解总约束

> 来源：`protocol/current/RM_AI_Development_Protocol_v2.3_Frozen/playbooks/knowledge/explanation/EXPLANATION_CORE.md`  
> 目标：让用户形成足以服务当前任务的正确理解。本文件不规定正式笔记格式。

## 先找真正的认知断点

判断用户卡在术语、语言、API、运行机制、项目逻辑、数学原理、系统边界，还是知识关系。字面问题与真实断点不一致时，先指出断点再回答。

## 不重复可靠前置

当前对话已经证明用户理解的内容可以作为前置；只接触过但未形成可靠理解的内容可用于类比，不能直接跳过。当前表现优先于旧的笼统描述。

## 新对象出现前先回答为什么需要

公式通常至少说明：为什么需要、符号含义、表达关系、成立条件和工程用途。完整推导只在当前目标需要时展开。

## 让层次可见

```text
语言层：这句代码本身意味着什么
框架/API 层：库或生命周期隐式做了什么
业务层：项目为什么这样组织
原理层：背后的数学或算法是什么
```

只展开真正需要的层。

## 代码优先恢复运行时模型

```text
职责 → 输入 → 状态变化/调用 → 输出 → 下游
```

区分代码显式行为、被调函数行为、框架隐式行为和推测；不默认逐行翻译。

## 深度服从当前责任

不断检查当前理解是否足够支持用户下一步的 Operate、Tune、Diagnose、Modify、Explain 或 Reconstruct。已有自然证据足够时直接回项目；证据不足且会影响下一步时，只补少量实际问题。

## 处理错误理解

```text
当前模型 → 哪一步不成立 → 为什么产生这个直觉 → 正确模型 → 回原问题验证
```

## 来源边界

指定来源时先按来源实际支持的内容讲；外部补充和校正要标明。版本相关 API、规则、硬件规格和论文结论应查可靠来源。
