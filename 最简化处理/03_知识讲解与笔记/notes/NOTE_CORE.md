# Note Core — 正式技术笔记总约束

> 来源：`protocol/current/RM_AI_Development_Protocol_v2.3_Frozen/playbooks/knowledge/notes/NOTE_CORE.md`  
> 按知识依赖组织，不按聊天顺序组织；讲解可以展开，笔记必须收紧。

## 一篇笔记只有一条主线

先回答“这篇到底解决什么”。多个概念可以共存，只要服务同一中心问题；出现第二条独立主线时再拆篇。

## 按知识依赖重组

推荐结构：

```text
本质
→ 前置对象
→ 核心概念或机制
→ 关键关系与为什么成立
→ 工程意义
→ 易混点与边界
→ 回到系统位置
```

不要照抄聊天顺序。

## 快速复习信息前置

第一屏优先放一句话本质、最重要关系、核心图/公式/API/流程和最需要记住的结论，不先铺大段背景。

## 讲解展开，笔记收紧

删除聊天式过渡、同义重复、无长期价值的争论和无关背景；保留最终正确模型、关键因果链、易混纠错和对后续知识有接口价值的结论。

## 事实、解释和推断分层

来源未支持的内容不能伪装成来源事实。按需使用“直观理解”“工程理解”“知识校正”“待验证”等标记。

## 主干自洽

链接负责继续深入，不能替代当前主线所需的最小解释。

## 图、公式和代码承担认知任务

每个元素都应回答“为什么必须出现在这里”。不为填空加图，不因理论主题堆公式，不复制无关大段源码。

## 生成流程

```text
检查已有同职责笔记
→ 判断 New / Update / Merge / Legacy Reconstruction
→ 确定中心问题和依赖链
→ 设计第一屏
→ 写主干与边界
→ 回到工程位置
→ 删除聊天残留和重复
```
