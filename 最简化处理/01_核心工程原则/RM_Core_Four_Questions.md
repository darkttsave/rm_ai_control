# RM 工程四问

> 来源：`protocol/current/RM_AI_Development_Protocol_v2.3_Frozen/human/RM_Core_Four_Questions.md`  
> 用途：过滤新的任务、架构、工具和流程是否真正服务 RM 工程。

## 1. 为什么造？

这个任务解决什么真实问题，为什么现在值得做？

至少逐渐弄清：当前瓶颈、比赛价值、与规则及其他组的关系，以及哪些前提变化会改变优先级。

## 2. 造不造得出来？

能否在真实时间、硬件和团队约束下形成完整闭环：

```text
真实输入 → 算法/状态 → 通信/决策 → 执行 → 机器人完成任务
```

理论可行、局部 Demo 或无法在 Deadline 前交付，都不等于工程上造得出来。

## 3. 稳不稳定？

- 运行稳定：失败行为、超时、限幅、性能和真实环境可重复性。
- 工程稳定：职责与接口清楚，修改不牵动大量无关代码，临时方案不会永久化。
- 团队稳定：不是只有原作者能维护，关键入口、参数和故障处理能够被接管。

## 4. 出了问题会不会修？

```text
观察现象
→ 区分 Fact / Hypothesis / Unknown
→ 理清关键链路
→ 缩小故障域
→ 设计高信息量实验
→ 修改并验证
```

“复制日志给 AI，不断试 A/B/C”不等于已经掌握系统。

## 安全是硬边界

涉及执行器、机械、能源或人员风险时，不能用不可接受的安全风险交换性能、进度或实现简单度。

## 新复杂度过滤器

面对新的 Framework、角色、模板、工具或流程，检查它是否明显帮助四问中的至少一项。若都不能，默认不加入。
