# 向下游发布执行提示词

> 适用角色：分对话  
> 重组来源：`Handoff_Protocol.md`、`TASK_BRIEF_TEMPLATE.md`、`Carry_Forward.md`

提示词负责说明目标、边界、材料入口和验收，不承担保存整个项目历史的职责。

## 判断 Cold Start 与 Warm Start

判断依据不是是否开启了新对话，而是执行体是否拥有可靠上下文。

- **Cold Start**：执行体第一次进入项目，或无法可靠读取当前任务状态。
- **Warm Start**：执行体已经理解项目与当前任务，只需要接收本轮差量。
- 无法确认时按 Cold Start 处理。

## Cold Start

建议正文 `600～1200` 个中文字符。已有背景、代码和日志通过路径引用，不复制整个 README、协议或聊天记录。

```markdown
# Cold Start 执行提示词

## 执行职责

## 项目最小背景

## 本次目标

## 已确认事实

## Scope
- Allowed：
- Not in scope：

## 必须保持不变

## 材料入口
- Repository / Branch：
- Tuning Manual / Task Log：
- Required Files：

## 预期结果

## 验证要求

## 停止并询问的条件

## 完成后反馈
使用《反馈执行结果》模板。
```

## Warm Start

建议正文 `200～500` 个中文字符。只传变化，不重新介绍项目结构和未变化的约束。

```markdown
# Warm Start 执行提示词

## 已有任务入口

## 本轮新增变化

## 本轮具体动作

## 变化后的边界

## 验证目标

## 完成后反馈
使用《反馈执行结果》模板。
```

缺失信息会改变 Goal、Scope、外部行为、安全或 Verification 时，执行体必须停止猜测并请求分对话或 Human 决定。
