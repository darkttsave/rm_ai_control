# 管理上下文生命周期

> 适用角色：分对话  
> 重组来源：`Context_Health.md`、`Conversation_Continuity.md`、`Carry_Forward.md`、`STAGE_CHECKPOINT_TEMPLATE.md`

分对话负责自己的上下文健康。总监督不负责日常提醒、整理或恢复。

## 上下文健康

- **Green**：目标、事实、决定、工作位置和下一步清楚，继续工作。
- **Yellow**：出现模糊回忆、支线混淆、重要结论变化或准备高风险修改；重新读取完成当前动作所需的最小材料。
- **Red**：无法可靠恢复 Goal、关键事实或 Scope；停止重大判断，先从 GitHub、调参手册和任务日志恢复。

不要按固定消息数检查。当目标改变、重要决定完成、长支线返回、新证据推翻旧假设、准备高风险修改或准备换对话时检查。

## 同任务换对话

角色、项目和任务不变时，续接内容建议控制在 `300～600` 个中文字符。它不是项目冷启动，也不是向总监督汇报。

```markdown
# 同任务续接

## 角色引用
角色名称或角色文件路径，不复制完整定义。

## 当前目标

## 已完成并验证

## 当前工作位置

## 已锁定决定与边界

## 材料入口
- Repository / Branch：
- Tuning Manual / Task Log：
- Other：

## 未解决问题

## 第一下一步
新对话收到后立即执行的动作。
```

## 何时上报总监督

只有上下文恢复后发现主目标、Scope、主线事实或关键决策需要改变时，才使用《向上游提交任务汇报》。单纯换对话不需要上报。
