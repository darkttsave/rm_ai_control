## 3 + 2 + 1

| 角色 | 数量 | 职责 |
|---|---:|---|
| 总监督 | 1 | 创建分对话 |
| 分对话 | 3 | 向上游汇报、向下游派任务、管理自身上下文生命周期 |
| 执行体 | 2 | 向分对话反馈、向另一个执行体交接工作现场 |

总监督只负责建立分对话和处理确实需要上收的决定。分对话负责自己的日常连续性与上下游协作。执行体负责完成具体工作并留下可验证、可接管的现场。

## 信息来源优先级

1. **GitHub / Git**：代码、配置、提交、分支、PR 和正式文件状态。
2. **调参手册 / 任务日志**：测试条件、参数变化、现象、分析和结论。
3. **书面报告或交接词**：结果摘要、边界、阻塞、工作区现场和下一步。
4. **聊天记录**：不作为长期事实来源。

GitHub 保存“做了什么”，调参手册保存“为什么这样做、测试结果如何”，报告与交接只补充“当前怎样继续”。

## 使用原则

1. 真实问题优先，不为未来假想需求扩充流程。
2. 冷启动传最小基线；已有可靠上下文时只传变化。
3. 提示词负责索引和边界，仓库与日志负责保存事实和产物。
4. 已有材料能回答的问题只引用路径，不重复抄写。
5. 事实、推测、决定和未知必须分开。
6. 缺失信息会改变目标、范围、外部行为、安全或验收时，触发 Human Gate。
7. 原 Frozen Protocol、Control、Authority、Archive 和历史模板保持原样；本目录不要求维护 Manager、Curator、Capability 或 Artifact Lifecycle。
